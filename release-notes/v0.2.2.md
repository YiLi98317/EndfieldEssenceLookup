# v0.2.2 — Version Calendar and release workflow fix

This release adds a Version Calendar page with every archived Endfield version calendar, keeps it up to date automatically, and fixes the desktop release pipeline.

## Downloads

- **macOS**: Download the `.dmg`
- **Windows**: Download the `.exe`

## Changes since v0.2.0

- **Version Calendar page**: the official title, timeline, and event images for versions 1.1–1.5
- The title and timeline stay pinned while you scroll, with dates lined up to the event columns
- Version picker with release dates; the latest version is selected by default (1.0 is listed but has no archived calendar)
- New side menu to switch between Essence Lookup and Version Calendar, with the EN / 中文 language switch
- Historical calendars recovered from the Wayback Machine and archived in the repository
- Style fixes
- **CI/CD**: a daily GitHub Action checks the official website, saves any new version calendar with its original images, and redeploys the site (`npm run sync:calendar` runs the same check locally)
- **CI/CD**: fixed desktop releases failing because the workflow pushed a version-bump commit to the protected `main` branch
- **CI/CD**: one Release workflow replaces three; the version in `package.json` is the release version, and merging a `release`-labeled PR tags the merged commit and publishes the builds
- **CI/CD**: an existing release can be rebuilt by running the Release workflow manually with its tag

## Notes

- v0.2.1 was never published: its release run failed, so this is the first release with the Version Calendar.
- New versions found automatically are listed by version number only (for example `1.6`) until their name is added to `src/data/versionCalendars.json`.
- A new calendar's release date is the day it was first detected.
- macOS builds are **not signed/notarized** yet (Gatekeeper may warn on first open; use right-click → Open).
